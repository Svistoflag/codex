# LEGAT Data Preparation Module (LDPM)

**Классификация:** СЛУЖЕБНО / ВНУТРЕННИЙ КОНТУР

## 0. Языковая политика
- Основной и единственный язык системы — **русский**.
- Весь пользовательский интерфейс, визуализация, отчёты, логи, сообщения об ошибках, названия полей, фильтры и экспортируемые данные отображаются исключительно на русском языке.
- Английский язык допустим только в программном коде, идентификаторах БД и внутренних API — пользователю не отображается.

## 1. Назначение системы
Веб-приложение предназначено для:
- загрузки Excel-файлов фиксированного формата и структуры;
- автоматической классификации строк входного файла;
- нормализации, очистки и структурирования данных;
- дедупликации записей;
- географической нормализации адресов;
- визуального контроля процесса обработки данных;
- интерактивной фильтрации и сегментации данных;
- гибкого экспорта подготовленных наборов данных;
- подготовки данных к следующему аналитическому этапу.

Система является техническим подготовительным модулем. Аналитические выводы и оценка рисков **не** выполняются.

## 2. Входные данные
**Поддерживаемый формат:** Microsoft Excel (.xlsx)

**Структура файла:**
- 1 лист;
- без заголовков;
- до 14 колонок;
- смешанные типы строк.

**Типы строк:**
- `PURCHASE_ROW` (покупка);
- `PROFILE_ROW` (профиль/контакт);
- `INVALID_ROW` (некорректная строка).

## 3. Детекция типов строк
Каждая строка классифицируется автоматически:
- `column[0] = DATETIME` → `PURCHASE_ROW`
- `column[0] = INTEGER` **и** `column[1]` содержит "Пункт выдачи" **или** "Постамат" → `PROFILE_ROW`
- иначе → `INVALID_ROW`

**INVALID_ROW:**
- исключается из обработки;
- сохраняется в журнал ошибок.

## 4. Схема данных `PURCHASE_ROW`
- `column[0]` → `purchase_datetime`
- `column[1]` → `order_line_id`
- `column[2]` → `product_id`
- `column[3]` → `product_name_raw`
- `column[4]` → `order_base_id` (не является ID человека)
- `column[5]` → `pickup_address_raw`
- `column[6]` → `order_base_id_dup`
- `column[7]` → `phone_raw`
- `column[8]` → `email_raw`
- `column[9]` → `last_name_raw`
- `column[10]` → `first_name_raw`
- `column[11]` → `profile_datetime_raw`
- `column[12]` → `ip1_raw`
- `column[13]` → `ip2_raw`

## 5. Схема данных `PROFILE_ROW`
- `column[0]` → `profile_id_raw`
- `column[1]` → `pickup_address_raw`
- `column[2]` → `profile_id_dup`
- `column[3]` → `phone_raw`
- `column[4]` → `email_raw`
- `column[5]` → `last_name_raw`
- `column[6]` → `first_name_raw`
- `column[7]` → `profile_created_datetime`
- `column[8]` → `ip1_raw`
- `column[9]` → `ip2_raw`

## 6. Нормализация данных
- Телефоны → формат `7XXXXXXXXXX`.
- Email → `lowercase` + базовая валидация.
- ФИО → Title Case.
- Даты → ISO datetime.
- IP → валидация IPv4 / IPv6.
- Наименования товаров → очистка и нормализация строк.

## 7. Дедупликация
- Полные дубли строк → удаляются.
- Дубли профилей → сворачиваются.
- Все операции дедупликации логируются.

## 8. Географическая нормализация
**Вход:** `pickup_address_raw`

**Выход:**
- страна;
- регион;
- город / населённый пункт;
- район (если доступен);
- тип населённого пункта;
- нормализованный адрес.

**Поддержка:**
- словари;
- регулярные выражения;
- ручная корректировка;
- сохранение правил нормализации.

## 9. Связка профилей и покупок
**Ключи связывания:**
- PRIMARY: телефон;
- SECONDARY: email;
- TERTIARY: ФИО + город.

**Покупка без профиля:**
- создаётся временный профиль (`TEMP_PROFILE`).

## 10. Визуальный модуль мониторинга
Отдельный экран "Процесс обработки":

**Этапы:**
1. Загрузка файла
2. Анализ структуры
3. Детекция типов строк
4. Нормализация данных
5. Дедупликация
6. Географическая нормализация
7. Формирование таблиц
8. Генерация отчёта

Для каждого этапа:
- статус;
- прогресс;
- время выполнения;
- анимация активного состояния.

## 11. Инфографика и статистика
Отображается в реальном времени:
- общее количество строк;
- количество покупок;
- количество профилей;
- количество дублей;
- количество ошибок;
- % нормализации;
- % гео-распознавания.

**Типы визуализации:**
- прогресс-бары;
- счётчики;
- диаграммы;
- flow-анимации.

## 12. Ошибки и технические логи
- live-log обработки;
- группировка ошибок по типам;
- переход к проблемным строкам;
- экспорт журналов ошибок.

## 13. Модуль фильтрации и сегментации
После завершения обработки пользователь может:

**Фильтровать данные по:**
- региону;
- городу;
- району;
- ПВЗ;
- типу строки;
- периоду;
- товарам;
- контактным данным.

**Поддержка:**
- множественный выбор;
- AND / OR условия;
- ручной выбор строк;
- сохранение наборов фильтров.

## 14. Автоматическая сегментация
Система автоматически формирует сегменты:
- по регионам;
- по городам;
- по районам;
- по ПВЗ.

Каждый сегмент:
- отображается как отдельный блок;
- имеет счётчики;
- доступен для экспорта.

## 15. Гибкий экспорт данных
Экспорт выполняется **на основе активных фильтров**.

**Форматы:**
- CSV;
- XLSX;
- JSON.

**Варианты:**
- все отфильтрованные данные;
- только покупки;
- только профили;
- по городам (раздельные файлы);
- по районам;
- по выбранным позициям.

**Поддержка:**
- ZIP-экспорт;
- автоматическая разбивка по сегментам.

## 16. Отчёт об экспорте
Для каждого экспорта формируется отчёт:
- применённые фильтры;
- объём данных;
- структура;
- дата и время.

## 17. Архитектура
- **Frontend:** SPA веб-приложение.
- **Backend:** REST API, асинхронная обработка, очередь задач.
- **Realtime:** WebSocket / SSE.

## 18. Безопасность
- ролевая модель доступа;
- аудит действий пользователей;
- хранение файлов внутри контура.

## 19. Результат работы системы
Система предоставляет:
- полностью нормализованные данные;
- структурированные таблицы;
- визуальный контроль обработки;
- гибкую фильтрацию;
- сегментированные выгрузки;
- готовность данных к аналитике.

Система является обязательным этапом перед передачей данных в аналитические и оперативные модули.
